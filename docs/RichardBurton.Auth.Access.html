    RichardBurton.Auth.Access (richard_burton v0.1.0)

    Broadcasts that a person's access may have changed, on a PubSub topic for that person.

    topic/1 names the topic, and changed/1 broadcasts :access_changed on it. The message does not say what changed. A subscriber reads the current state from the database when it receives one, so the order of the messages does not matter, and an extra message costs only one more read.

    Call changed/1 after the change is committed. A subscriber reads on its own database connection, so it cannot see the change until the transaction that makes it commits.

    Functions
