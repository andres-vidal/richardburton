    RichardBurton.Publication.Index (richard_burton v0.1.0)

    Full-text search over the publication index.

    A term is split on :or (or :ou) into alternatives, and a publication matches if it satisfies any one of them.

    Each alternative contains free words and operators. Free words are matched one at a time and combined with AND, so every word has to match. An operator restricts its value to a single field:

    title:casmurro            search the title only
autor:machado             search the author, written in Portuguese
year:1950-1960            a range of years
-country:US               exclude
title:"dom casmurro"      these words, in this order

    An alternative matches when both its words and its operators match.

    Terms used here, which also appear as tags in the code:

    • spelled out — a term that uses quotes or a leading - but contains no operator. Postgres already understands that syntax, so the term is handed to websearch_to_tsquery as written instead of being parsed here. Tagged {:spelled_out, term}.
    • criteria — what a term becomes once it has been read: either {:spelled_out, term} or {:alternatives, alternatives}. matches/1 and ranking/1 are built from it, and it is the only thing that differs between the two ways of reading a term.
    • listed row — a publication as a page of the index holds it: a RichardBurton.FlatPublication read from the view, with excerpts and marked. Its notes are nil, whatever notes the publication has, and its JSON has no notes key, so that a page stays small however long the notes are. details/3 and without_sources/0 return listed rows. all/1 and search/2 return FlatPublication structs whose notes are read from the publications table, or maps of the fields they are asked for.

    Each word is matched on its own: as a prefix when the index holds words beginning with it, and by resemblance when it does not. So a word matched by resemblance does not change how the words beside it match, and the query is run once.

    How each word matched is its standing (see RichardBurton.Publication.Index.Keywords). standings/1 looks up the standings of all of a term's words with one query. search_order/2, details/3 and matching/2 take those standings along with the term, so that several of them can read one lookup. Given the term alone, each of them looks the standings up itself.

    Both ways of reading a term match against a tsvector whose accents have been stripped, so the term has its accents stripped too before it is compared. See RichardBurton.Publication.Index.Term for the vocabulary a term is written in and the names each operator answers to.

    Returns the listed rows for the given ids, in that order: one page of an ordering that search_order/1 or all_order/0 returned earlier.

    Pass nil as the term for a plain listing, whose rows hold nil excerpts and marked. Pass the term itself and each row comes back with an excerpt of every field that matched it.

    search(term, list)

    Returns the publications a term matches.

    The term is split on :or (or :ou) into alternatives, and a publication matches if it satisfies any one of them. Within an alternative, words are combined with AND, so every word has to match. So searching a full title returns only that title, while "one title :or another" returns both.

    A word matches the indexed words it begins, so a half-typed word matches every word it might become. A word that begins none matches the indexed words it resembles, and a word that resembles none is dropped rather than emptying the result.

    It returns {:ok, publications}, every match at once, in the order search_order/1 gives, as maps of the fields in attributes, or whole, with their notes, when attributes is empty. The notes are read from the publications table in the same query. search_order/1 and details/2 read the same matches a page at a time.

    search_order(term)

    The ids of every publication a term matches, in the order they should be read, or :none if the term matches nothing at all.

    The order is decided once, here. The reader then pages through those ids with details/2 and sees a stable list, because the order was fixed at the moment the search ran. Without that, rows could shift, be skipped or appear twice as the database changed between one page and the next.
