    RichardBurtonWeb.PublicationController (richard_burton v0.1.0)

    The publication endpoints: listing, searching and exporting the index, validating publications, the writes (insert, update, merge, delete, restore and undo), the history, and the duplicate review.

    The index is paged by a fixed order rather than by offset. The first response to a listing or a search holds the ids of every publication it matches, in reading order, and the rows of the first page. A later page is requested by the ids it holds.

    A publication read from the index, such as a row of a listing, a publication in a duplicate cluster, or a stored publication that a row resembles, has no notes key (see RichardBurton.FlatPublication). A publication that show/2, index_deleted/2 or a write responds with holds its notes, or null when it has none.

    A path id that is not a whole number is a 404, as RichardBurtonWeb.Params.id/1 says. A write that would give a publication the composite key of another is a 409 whose body holds error: "conflict" and, when the response names it, publication, the other publication.

    Functions

    create_all(conn, map)

    Inserts the publications in the request body, all or none, and responds with them, flattened, as a 201.

    When one of them has the composite key of a stored publication or of an earlier one in the body, nothing is inserted, and the response is a 409 with error: "conflict" and publication, the first publication that repeats a key. When one is invalid, the response is a 400 with error: "invalid", publication, the first invalid one, and its errors.

    history(conn, arg2)

    Responds with entries, the history entries of the publication id, or of every publication when there is no id, newest first. Without an id, each rename is one entry (see Publication.History.all/0).

    Each entry's snapshot holds the publication's fields after the change, except its notes. A change to the notes is in the entry's diff. The snapshots in others are whole. name_change holds the name change of a rename's entry (see Publication.History), and is null on the entries of every other action.

    index(conn, params)

    Lists the publications in the index.

    Without ids, the response holds order, the ids of every publication the search parameter matches, or of every publication when there is no search; entries, the rows of the first per_page of them; per_page; and matched, which is Publication.Index.Excerpt.resolution/2 for the search, or nil. The words of the search are looked up once, for all three.

    With ids, the response holds entries alone: the rows of those ids in the order given, with the excerpts of search when there is one. An id that is not a whole number is left out. Reading later pages by id against a fixed order keeps them stable when publications are added or deleted between requests.

    With unsourced, the response holds entries, every publication without sources, ordered by id.

    Every response but the one for ids puts the number of publications in the index in the count header (see Publication.Index.count_header/0).

    Each entry is a listed row, which holds every flat field but notes (see Publication.Index).

    index_deleted(conn, params)

    Responds with entries, the publications that are deleted now, each with its deleted_at, newest deletion first. A publication that was deleted, restored and deleted again is listed once. See Publication.all_deleted/0.

    merge(conn, params)

    Merges the publications with the ids in losers into the publication id, and responds with the merged publication, flattened. See Publication.merge/4.

    When the body holds notes, they become the merged publication's notes. They are validated as the notes of an update are, and null or blank notes leave the merged publication without notes. Without notes, the merged notes are the winner's followed by the losers', as Publication.merge/4 describes.

    Merging a publication into itself, or naming no losers, is a 400, rather than the 409 that self is elsewhere. A merged publication with the composite key of another publication is a 409 with error: "conflict". A merged publication that is invalid is a 400 with its errors. They are {notes: "malformed"} for notes that are not rich text, and {notes: "too_long"} for notes whose text is longer than 10,000 characters, whether the body gave them or the merge joined them.

    reconsider(conn, arg2)

    Removes what distinguish/2 recorded about the publications with the ids in publications, so duplicates/2 can report them together again. Naming fewer than two is a 400 with not_enough.

    resemblances(conn, map)

    Responds with entries, the result of Publication.Duplicates.resemblances/1 for the rows in the request body. The rows are publications that are not stored yet, so each entry names its row by its position in the list.

    restore(conn, params)

    Restores the deleted publication id. A body with the publication's fields is applied to it first, as an edit, so that a restore that would conflict can be made with changes.

    When another publication that is not deleted has the same composite key, the response is a 409 with error: "conflict" and that publication. A publication that a merge absorbed is a 409 with error: "absorbed", because only undoing the merge brings it back.

    show(conn, params)

    Responds with the publication id, flattened, with its notes, its kind and follows. With a search, the publication holds the excerpts and marks of that search, as in the index. A deleted publication is a 404.

    kind is "first_translation", "retranslation" or "reissue", and follows lists the publications a retranslation or a reissue follows, in ascending order of id. Each of them holds its id, title, year, authors (its translators), publishers and countries. follows is an empty list for a first translation. Publication.Kind defines both.

    undo(conn, map)

    Undoes the history entry version of the publication id. See Publication.undo/3, which decides whether the entry can still be undone and how. An entry that cannot be undone is a 409 with error: "conflict".

    update(conn, params)

    Replaces the fields of the publication id with the flat fields in the request body, and responds with the publication, flattened. Invalid fields are a 400 whose errors are keyed by the same flat fields.

    validate(conn, params)

    Validates publications without writing them, and responds with each one and its errors, which are nil when it is valid.

    The publications come from the CSV file uploaded as csv, or from a list in the request body. A CSV file that cannot be read is a 400 whose error names the reason, such as invalid_escape_sequence.

    With an id, the request body is one publication, validated as an edit of the publication id, so that its own composite key is not a conflict.
