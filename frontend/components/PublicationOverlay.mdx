# Publication overlay

A publication shown over the page the reader came from — the database, usually.

It is **its own route**, `/publications/[id]`, intercepted into a slot beside the
page: following a row from the database opens this, while arriving at the same
address directly opens the publication's own page. That is what keeps it cheap:
opening it renders this and nothing else, so the database underneath is neither
read again nor sent again.

A row's link carries `?modal` (and the query it was found under), so the address
says not just _what_ is being shown but _over what_. Interception only applies to
navigation inside the app, so a **reload** reaches the page — which finds the
mark and draws the same thing, and the reader gets back what they were looking
at. A link from the copy button carries no mark: someone opening it cold has no
database to be shown over.

Closing goes back, because that is what opening it did — except where there is
nothing to go back to, which is exactly the reloaded case, and `closeTo` says
where instead.

The record is **read on the server** for that address and handed over unawaited,
so the overlay opens on the click and the record streams into it — the dialog
grows into the record when it arrives. A link to a publication outside the
current search opens it all the same, since the overlay reads the record from
the server rather than from the database's publication store. The overlay
gives the view a publication store of its own.

## What it renders

The publication is laid out as a searchable [`Article`](?path=/docs/components-article--docs):
the title and translators as the heading, and a prose description whose fields
(original title, authors, countries, publishers) are `Searchable` links that
navigate to a filtered index. The view itself is
[`PublicationDetail`](?path=/docs/publications-publication-detail--docs), the same
one the publication's own page renders; the overlay adds the heading and a subtle
[copy link](?path=/docs/components-copy-link--docs) beside it, which hands out the
very address the overlay is at.

## Props

- `view` — a promise of the record read for its address, or of `null` when there
  is nothing there. Unawaited on purpose; the overlay suspends on it, showing a
  placeholder in the record's shape so the dialog barely moves when it lands.
- `closeTo` — where closing goes when there is no history to go back through (a
  reader who reloaded). Left out when the overlay was followed from the
  database.

## States

- **Default** — the record, as a reader sees it (above).
- **Streaming** — the read still in flight: the placeholder holds the record's
  place, within a few pixels of the size it will take.
- **With history** — an admin's read brings the mutation log with the record.
- **Missing** — a link to a deleted record says so instead of opening empty.
- **Long heading** — a title too long for the row truncates, so the copy link
  keeps its place.

There is no closed state: a closed overlay is the route not matching, and the
slot renders nothing.

## Admin actions

For an admin the view gains an action row: **Edit** switches the dialog to an
inline edit form (`PUT /publications/:id` on save), and **Delete** removes the
record server-side — guarded by a
[confirmation](?path=/docs/components-confirmation-modal--docs) that names the
publication before anything happens. Cancelling the confirmation backs out
without consequence; confirming closes the dialog and drops the row from the
index. An admin also gets a collapsed **History** section — the record's
[mutation log](?path=/docs/publications-publication-history--docs), read together
with the record rather than fetched on expand.

## Closing with an unsaved edit

Closing the overlay, with <kbd>Esc</kbd>, the close button or a press outside
the dialog, closes it at once, unless the edit form holds changes that are not
saved. The overlay is an [edit modal](?path=/docs/publications-edit-modal--docs),
so it then stays open and a
[confirmation](?path=/docs/components-confirmation-modal--docs) asks whether to
discard them. Cancel, or <kbd>Esc</kbd> in the confirmation, goes back to the
form with the changes as they were typed. The form's own Cancel button discards
the changes without asking.
