# Publication index table

The **desktop** presentation of the publication index — one column per
publication attribute, one row per publication. It is read-only on its own; the
editable [review](?path=/docs/publications-workspace--docs) is built by extending
it (see _Extension points_ below).

## Data source

Like the [index list](?path=/docs/publications-index-list--docs), the table is
**state-driven** and takes no publication props — it reads the row ids from
the store (`usePublicationIds`) and each cell reads its own value. A cell shows
the saved value, as the search marked it, so a country code shows as the
country's name and an unsaved edit does not show. Stories seed the store with
the shared fixtures:

```tsx
import { seedIndex } from "test/publication-fixtures";

seedIndex(store);
```

## Column visibility & virtualization

- **Toggleable columns** — the `ColumnMenu` (next to the search bar) shows or hides
  attributes; visibility is driven by the store (`useIsAttributeVisible` /
  `setAttributesVisible`). Hidden columns simply don't render — no header, no cells,
  no grid track — so the visible columns re-share the width with nothing to animate.
- **Row virtualization** — each row only renders its cells once scrolled into
  view (`useVisible`, an `IntersectionObserver`), keeping long result sets cheap.
  This is why story assertions count `role="row"` rather than reading cell text —
  off-screen cells aren't mounted yet.

## States

- **Populated** — the sample above.
- **Empty** — ids loaded and none to show, because the database is empty or
  the search matched nothing; renders `EmptySearchResults`
  ([Empty](?path=/story/publications-index-table--empty) story).
- **Loading** — ids not loaded; renders a
  [`PublicationIndexTableSkeleton`](?path=/docs/publications-index-table-skeleton--docs)
  in the table's own columns.

## Loading

While the ids have not loaded, the table renders a skeleton in its grid, with
the same column template as its rows. The skeleton's header holds the labels
of the columns the table shows, and its cells have the shapes of their
attributes' values.

## Extension points

The table accepts pieces that replace its own: `ExtendedRow`, `ExtendedColumn`
and `ExtendedContent`, which default to the read-only row, cell and cell
content. `ExtendedSignalColumn` adds a cell before the attributes of every row,
`ExtendedTrailingColumns` add cells after them, each with a column named for
screen readers, and `ExtraRow` adds a row at the end.
[`PublicationWorkspace`](?path=/docs/publications-workspace--docs) builds the
editable table from these.

## Props

- `onRowClick(id, event)` — called when a row is clicked. Rows are memoised, so
  a function that keeps its identity lets a row skip rendering when only the
  table renders again.
- `rowHref(id)` — the address of a row's record. With it, the title cell is a
  link.
- `selectable` — whether the text in the table can be selected.
- `collapsible` — whether the column menu can hide columns. With `false`
  every column shows.
