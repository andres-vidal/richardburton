# Resemblance counter

A button with the number of rows in an import that resemble a stored
publication or another row. Pressing it opens the resemblance review. It sits in
the workspace footer beside the
[error counter](?path=/docs/publications-publication-error-counter--docs).

The composite key rejects a row that exactly repeats a stored record. This
counter finds the near-matches that the key lets through: a typo, a dropped
accent, or a translator entered as "R. Burton" once and "Richard Burton" the
next time. Without it, those rows import without errors and only appear later
in the [duplicate review](?path=/docs/publications-duplicate-review--docs), once
they are stored.

Each row is compared with the stored records and with the other rows of the
same import. The second comparison finds near-duplicates inside one CSV, which
are not in the database yet.

A row does not count against a record or row with another year, another
country or another publisher, because that is another edition. A field that one
of them leaves empty does not rule anything out, so a row being filled in is
counted as soon as its title and translators resemble something.

## When the check runs

The check runs by itself as rows are edited, the same way validation does.
`CheckResemblances` watches every field the rule reads, which is all of them
except the sources, on every row. It runs the check 500 ms after the
last change to one of those fields. Editing a row's sources does not run the
check.

Each check sends every row, not only the row that changed, because each
row is also compared with the other rows. Editing one row can make it resemble
another row that has not changed. The comparison between rows is the expensive
part of the check, and its cost grows with the square of the number of rows.
See `Publication.Duplicates.resemblances/1`.

When one of those fields changes, the row's result is cleared straight away,
because it describes the old values. The count falls, and rises again if the
next check finds that the row still resembles something.

## States

- **Found** — the count, as a button that opens the review.
- **Nothing alike** — no button. The error counter already reports when a set
  is valid.
- **Moving a row out lowers it** — a row moved to another document leaves the
  count. So does editing a row so that it no longer resembles anything.

## The look-alike button on each row

Each row that resembles something also has a look-alike button. Its tooltip
names the stored records the row resembles by title and year, and gives the
number of other rows of the import it resembles. Pressing it opens the review on
that row, not at the start of the queue.

The button is at the end of the row, beside the sources button, not in the
leading cell. The leading cell is the row's selection handle. It is 2.5rem wide
around a 1.25rem icon, so a button there would take clicks meant to select the
row.

Because two controls open the review, whether it is open, and on which row, is
kept in the store, in `reviewingAtom`, not in this component. The workspace
renders the review from that atom, so it opens the same way from either control.
`resetAll` resets the atom, which closes the review when the working set is
cleared.

## Links to stored records

Each stored record in the review links to its own page. The link opens in a new
tab, so the review and the workspace stay open.

## What it is not

A look-alike is not an error. It does not make a row invalid and it does not
block a submit, because a row that leaves out its year, country or publisher
can resemble another edition of its book, and both editions belong in the
database. The check also stores nothing. A row has no id yet, so there is no
pair to rule apart the way the duplicate review does.
