# Highlight

Renders the marks the index put on an excerpt, so a reader can see what the query
caught rather than inferring it. Used wherever a publication is shown while a
search is on — the rows of the index, the list, and a record open over them.

<Canvas of={HighlightStories.Matched} />

## Props

- `children` — the excerpt to render. A plain string; the component returns it as
  a mix of text and `<mark>` runs.
- `className` — the classes each `<mark>` carries. Defaults to the amber mark the
  index uses.

## How it works

The index returns, for every field it searched, the text that matched with the
matched words wrapped in `[[ ]]` — see the backend's
`RichardBurton.Publication.Index.Excerpt`. This component splits on those
delimiters and wraps the odd runs in `<mark>`. It decides nothing about what
matched; it only renders what the database already decided.

That is the point of doing it this way. Whether two spellings are one word, where
a word ends, and which field an operator was scoped to are all settled by the
search configuration, and only the database knows them. `title:night` marks the
title and nothing else because the index built an excerpt for the title alone.

<Canvas of={HighlightStories.Accented} />

Accents survive: the index folds them away to decide a match, but the excerpt it
returns is the text as it is actually stored, so `Angústia` is marked by a search
for `angustia` without losing the accent from what is shown.

An excerpt can carry any number of marks, and all of them are rendered.

<Canvas of={HighlightStories.ManyMatches} />

## Outside a search

A field the search did not match has no excerpt, and the caller passes the stored
value instead — see `Publication.markedValue`. It carries no `[[ ]]`, so it
renders untouched. The same is true of any text read outside a search, such as a
publication's own page opened without a query behind it.
