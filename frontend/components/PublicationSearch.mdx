# Publication search

The search bar for the publication index — a single text input that filters the
list by keyword. It sits above the index table/list and drives what the rest of
the workspace shows.

## Data source

The input is **URL-driven**: on change it writes the current text to the
`search` query param (`router.replace`), and on mount it hydrates its value back
from that param, so a shared link reproduces the same search.

Typing therefore **navigates** rather than fetching: the results for a query are
read where the page is rendered, so the query living in the URL is all the page
needs. The navigation runs in a transition — what is on screen stays until the
new rows are ready — and is debounced, so a typist does not ask for a page per
letter. "Searching…" shows while what has been typed and what the URL says have
not met, or the page for it is still coming.

The report below the input is **state-driven** — it reads what the index made of
the term from the publication store (`useMatched`). Only the words the index read
differently from the way they were typed are there: a reader who typed `machado`
and is told the search was for `machado` has learnt nothing, so most searches
report nothing at all. A widened one reads `Maries matched marie, maria, mario`,
each word a link back to the term that would find it on its own — scoped to its
field, so following one narrows the same way.

It is one clipped line, with a "Show all" beside "How to search" that lets it
wrap to as many lines as it needs. The control is offered whenever there is a
report, since whether the line is actually clipped is a question only measuring
the rendered text answers, and the answer changes with every resize.

In stories the store is seeded through the shared fixtures:

```tsx
import { seed } from "modules/publication/fixtures";

seed(); // load the sample publications before the story renders
```

## States

- **Empty** — the default: the input renders with its placeholder and no report
  below it.
- **Typing** — entering text updates the input and, after a beat, the `search`
  param the page reads its rows for. See the
  [Typing](?path=/story/publications-publication-search--typing) story.
- **Searching** — the status line while the typed query and the URL have yet to
  meet.
- **Widened** — when the index answered a word with something other than itself,
  the line under the input says so, and opens in full on demand. See the
  [Widened](?path=/story/publications-publication-search--widened) story.
- **Taken as written** — nothing was widened, so nothing is reported and there is
  no control to open.
