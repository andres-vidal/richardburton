# Layout

The app shell every page renders inside: a sticky header (the branded banner
plus an optional `subheader`) and an optional sticky footer around a scrollable
`main` content slot. The page body scrolls while the header and footer stay
pinned.

## Slots

- `content` — the main page content (required).
- `subheader` — an optional band under the banner, inside the sticky header
  (e.g. a page's breadcrumb + `PageHeader`, or the search panel).
- `leftAside` — an optional left rail beside the content.
- `footer` — an optional sticky footer.

## Measure

- `full` (default) — the content fills the viewport. What the index and the bulk
  workspace need from their tables.
- `aligned` — the subheader and the content share one column of readable width,
  both starting at the page's own gutter, where the header's content begins. The
  pairing is the point: a page's breadcrumb and title line up with what they
  introduce, instead of a narrow column floating in the middle of an empty page.

## Signing out

The banner carries the way out, next to Learn More and Contact Us, whenever
there is a session. It is the one control that has to be reachable from every
page — a page you cannot leave from is a page you are stuck on — and the banner
is the only thing every page has. Pages that carry a footer do not repeat it.

<Canvas of={LayoutStories.SignedIn} />

## Sticky column headers

The header publishes its measured height as the `--app-header-h` CSS variable,
kept current by a `ResizeObserver`, so a table's column-header row can pin just
below the header — at the bottom of the subheader panel — rather than scrolling
behind it.
