# Workspace undo

Undoes and redoes edits made in the bulk-import workspace.

Undo does not return rows to the values in the uploaded CSV. The workspace's
content is a shared document that holds one value per field, so the imported
value is not kept once a field is edited.

## Undo covers only your own changes

Every edit made in this tab is applied with the `LOCAL` transaction origin, and
the Yjs `UndoManager` tracks only that origin. Undoing your last change
therefore leaves other people's changes alone. This is why undo does not simply
return the document to its previous state.

For the same reason, a reopened workspace has nothing to undo. Its rows were
loaded, not edited in this tab, so they do not have the `LOCAL` origin.

## What counts as one step

Edits made close together in time are merged into one step, so undo removes a
burst of typing as a whole word, not one letter at a time.

Adding a row is a separate undo step from typing into it, so undoing the
typing in a new row does not also remove the row.

## Keyboard shortcuts

Ctrl+Z (⌘Z on a Mac) undoes, and Ctrl+Shift+Z, Ctrl+Y or ⇧⌘Z redoes. The
buttons' tooltips name these keys. The keys are bound by `useUndoShortcuts`,
not by this component, so they work even when no button is rendered.

A key press in a text field is left to the browser, so the field undoes the
text typed in it rather than the last change to the document. A key press in
an open dialog is also left alone.

## Props

None. It uses the undo manager of the workspace store it renders in, through
`useWorkspaceUndo`.

## States

- **Nothing to undo** — a reopened workspace, or one with no edits in this tab
  yet. No button is rendered, not even a disabled one.
- **After an edit** — Undo is shown, and returns the row to its previous value.
- **And back again** — Redo appears after something has been undone.
