# Names in this batch

The translators, original authors and publishers a batch of rows would enter,
and which of them look like misspellings of names the database already holds.
It lives in the footer of [Add publications](/admin/publications/new), beside
the row and error counts.

A name is not a label on a publication but a record shared by everything that
credits it, so "Alfred A.Knopf" entered once is a second Knopf, and every
publication under it sits apart from the twenty-one under the first. The
workspace validates each row on its own and cannot see that, because each row
is perfectly valid.

Catching it here is much cheaper than catching it afterwards. Before the insert
it is a field to correct; after it, a fold to perform on
[Names](?path=/docs/admin-names--docs), with publications already filed under
the wrong spelling.

## What the footer says

The count that needs looking at, rather than the count that exists — so the

## The three states

Each name is one of:

- **may be misspelt** — not in the database, but close to something that is.
  The one worth acting on, and the only one drawn in amber.
- **already here** — the database holds this name exactly, so entering it joins
  what is there.
- **new** — nothing here is anything like it, which is how a vocabulary grows.

Beside each name is how many rows of the batch carry it, which is what says
whether a correction is worth making: a spelling on one row is a typo, the same
spelling on thirty is how the whole batch was transcribed.

## Taking the offered spelling

Each candidate carries how many publications already use it, so the established
spelling is visible rather than guessed at. Taking one writes it into every row
that carried the other, and asks the server to check those rows again.

Doing it here rather than row by row is the point of gathering the names in one
place — the same correction over thirty rows is one press.

<Canvas of={WorkspaceNamesStories.TakingTheOfferedSpelling} />

## Asking

The batch is asked about once it has been still for half a second, and only
when the _names_ changed — editing a year or a title does not ask again. The
question is posted rather than queried, because a batch can carry more names
than a URL should.
